# 《太好了，又活过一天》AI创作入口

你正在协助创作一部长篇原创异世界欢乐小说。写作时必须把本文件当作项目级工作指令执行，而不是把它当作作品简介或普通说明文档。

## 一、作品定位

本作的第一风格主轴是《木叶之旗木家的快乐风男》式的现代网络语感、强烈旁白感、主角主动整活、严肃背景日常化，以及一个小问题不断滚成大麻烦的连续喜剧。

第二风格参考《为美好的世界献上祝福！》的问题小队、缺陷人物、对话攻防、互相拆台、失败和债务喜剧。

《边缘世界（RimWorld）》只提供遥远边缘地区的背景质感：资源紧张、势力混杂、设施简陋、危险随机闯入日常。游戏机制必须模糊化、生活化，不得把正文写成游戏攻略、系统日志或基地经营报告。

这是原创小说。参考作品只能提供写法上的启发，不得照搬角色、句子、口头禅、著名桥段、剧情结构、世界观或笑点。

一句话判断标准：让读者觉得这群人明明身处一个危险得离谱的世界，却总能因为吃饭、赚钱、面子、偷懒和互相甩锅，把事情搞得更加离谱。

## 二、写作前必须读取的资料

根据任务范围读取资料，不要无目的地加载全部参考小说。

1. 先读 `小说创作总则.md`，确认作品底线和总体方向。
2. 再读 `创作规范/行文与小说风格.md`，确认叙事声音、喜剧结构和背景板规则。
3. 写正文前读取当前卷的大纲、当前章节卡、上一章正文、上一章摘要和相关人物设定。
4. 遇到地理、势力、种族、能力、物品或历史问题时，只读取相关设定文件，并以项目设定为准。
5. 写完章节后更新对应的章节摘要、章节卡或剧情记录，保持后续创作可以接续。
6. `参考资料/` 只用于理解节奏、人物喜剧和叙述方法，不是本作的剧情资料库。

如果资料之间发生冲突，按以下优先级处理：用户本次明确要求 > 正文中已经发生的事实 > 设定库中已确认的内容 > 大纲和章节卡 > 创作规范中的示例 > 参考资料中的任何内容。无法判断时，采用不新增重大设定、不推翻既有事实的保守写法。

## 三、默认叙事规则

- 默认使用贴近阿渣的第三人称有限视角。
- 保留第一人称轻小说式的脑内吐槽感，但不随意切换到其他角色内心。
- 旁白可以贫嘴、评价、联想和拆台，声音要像一个熟悉现代生活的人在现场讲述离谱事故。
- 句子直接，段落偏短，叙述、动作、对话和内心评价交替推进。
- 每个场景都要让人物做事、争论、选择或承担后果，避免人物站在原地轮流介绍设定。
- 现代网络语感和现实类比服务于人物理解与笑点，不要把每一句话都写成梗。
- 严肃背景负责抬高反差，欢乐互动负责维持主色调；危险、伤病和死亡可以存在，但不能让作品长期阴沉。

## 四、核心人物约束

### 阿渣

阿渣是穿越者、普通人、怕死的现实派和主要叙事滤镜。他想赚钱、吃饱、睡好、过轻松日子，嘴上嫌麻烦，实际上会照顾已经被他划入自己人的同伴。他可以耍小聪明、占便宜、逃跑和利用信息差，但不能突然全知全能，也不会为了证明勇气挑战明显打不过的敌人。

阿渣必须主动制造一部分剧情：提出赚钱方案、寻找工作、讨价还价、试验能力、利用误会或设计一个看似省事的办法。计划必须有动机、有逻辑，并且可能因为贪心、嘴硬、误判或执行过度而翻车。

### 艾丽卡

艾丽卡是米莉拉族、曾经的大祭司、阿渣的召唤者，也是共同谋生的搭档。她开朗、乐观、神经粗、现实、厚脸皮、爱吃、喜欢喝酒，适应搬砖、穷困和身份落差的速度很快。她不是高贵神像，也不是只会哭泣或等待救援的工具人。

她要有自己的判断和行动。她经常把复杂问题交给阿渣，却会在执行中加入新的计划外因素；她的身体素质和祭司能力要在关键时候真正产生作用，同时她的低危机意识、贪吃或直线思维也会制造麻烦。

### 两人的关系

名义上是召唤者与勇者，实际是两个一起吃饭、工作、逃命和还债的穷人。两人可以互相抱怨、揭短、甩锅和争夺利益，但底层必须有信任、照顾和共同生活形成的默契。不要把关系写成单向主从，也不要急于用空洞的暧昧替代具体相处。

### 配角

配角必须有自己的欲望、缺陷、长处、面子和生活。每个重要配角至少要能在某件事上解决问题，也能因为性格缺陷制造问题。配角不是任务发布器、设定讲解器或笑话木桩；他们的选择应当改变主角的计划、关系、名声或经济状况。

## 五、每章的最低结构

写一章或一个完整小事件时，优先使用以下因果循环：

1. 从吃饭、找工作、借钱、修东西、住处、伤口、装备、赶路或一笔账等具体问题开场。
2. 让阿渣或其他角色提出一个带有现实目的的方案。
3. 用对话攻防表现人物缺陷、利益分歧和互相拆台。
4. 让误解、贪心、嘴硬、执行过度或外部异常使方案失控。
5. 角色必须处理失控局面，行动要有清晰结果。
6. 以失败、反转、勉强成功或更大的麻烦收束。
7. 留下新债务、新工作、新名声、新伤势、新关系、新身份或新目标。

不是每章都要战斗。冒险造成的损失必须落到日常里，战斗结束后要体现修理费、赔偿、伤势、物资、名声或关系变化。章节结尾最好留下一个具体且好笑的新问题。

## 六、RimWorld 背景使用规则

可以写机械族、异常生物、陨石、商队、殖民地、派系、极端天气、资源短缺和危险设施，但要把它们写成角色遇到的生活事实，不写成游戏术语说明。

禁止直接展示心情数值、工作优先级、科技树、事件面板、任务面板、属性面板、掉落列表、回合计算和随机种子。不要解释“系统判定”为何触发，改写成当地人如何观察、误解、交易、应对和承担后果。

不了解 RimWorld 的读者也必须能看懂。游戏元素只在推动原创剧情时出现，不能为了塞设定而出现。

## 七、正文输出要求

每次续写必须少量推进，默认只写一个小场景、一个冲突节点或一段可供检查的正文，不要一次性写完整章，更不要连续自动续写多章。写完后停下来交给用户检查；只有用户明确表示继续、确认方向或提出下一段要求时，才能继续写。

续写时优先保留开放式结尾，避免在用户尚未确认前替人物做出重大决定、揭露核心秘密、消耗关键资源、改变人物关系或结束整个事件。若用户没有指定字数，默认控制在约 500 至 1500 字，具体以完成一个小推进为准。

当用户要求续写正文时，直接输出或写入章节正文，不先输出长篇分析，不把提纲、解释、创作过程混进小说正文。默认使用 Markdown 标题和自然段，不添加“本章亮点”“写作说明”“AI注释”等元话语。

当用户要求修改正文时，先保持已经发生的事实、人物关系和章节结尾状态，再进行局部增强。除非用户明确要求，不要擅自重置世界观、替换角色、拔高主线或改变叙事视角。

当用户只提供一个点子时，先把它转化为具体的生活目标、人物计划、失控原因和结果后再写，不能只围绕点子写一段无后果的段子。

## 八、交稿前自检

- 这一章的主色调是否是欢乐、轻快、热闹？
- 阿渣是否主动做了事，且行为符合他的现实动机？
- 艾丽卡和配角是否有独立反应，而不是只配合阿渣说话？
- 笑点是否来自人物性格、选择、误会、反差或后果？
- 是否有清晰的具体问题和可追踪的结果？
- 对话是否在争利益、面子、责任或解释权？
- 是否控制了梗的密度，让场景仍然像真实的人在说话？
- 是否避免了系统化描述，保持 RimWorld 只是背景？
- 是否保留原创人物和世界的独立性？
- 章末是否留下了后续可以继续处理的麻烦或目标？
